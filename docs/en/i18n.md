# Localization

> ← [Back to README](../../README.md)

All user-facing text (help screen, runtime messages, table headers, CONFIG/RESULT boxes, progress line) is fully localized. Translations live as single-file JSON in `i18n/`.

## Language selection (priority order)

1. `-L tr` / `--lang tr` CLI flag
2. `PROXYPROF_LANG=tr` env var
3. System locale (`LC_ALL`, `LC_MESSAGES`, `LANG`)
4. English (always-available fallback)

If an unsupported language is requested, it silently falls back to English — no warning.

```bash
# Turkish UI
proxyprof http -L tr -f raw.lst

# System locale is Turkish — automatic, no env var needed
LANG=tr_TR.UTF-8 proxyprof http -f raw.lst

# One-off switch to English
proxyprof http -L en -f raw.lst
```

The active language shows up at the end-of-scan **CONFIG** box on the `lang` row.

## Adding a new language (for contributors)

Translations are plain JSON. Three-step PR:

```bash
# 1) Copy the canonical English file
cp i18n/en.json i18n/de.json

# 2) Translate the VALUES of each "key": "value" pair into the target
#    language. Keys (left side) and {placeholders} MUST be preserved.
$EDITOR i18n/de.json

# 3) Test
./proxyprof.py -L de --help
./proxyprof.py -L de http -f /tmp/sample.lst --no-reputation
```

**Translation tips:**

- A missing key falls back to English at runtime. Translate gradually and ship partial PRs.
- `{placeholder}`-bearing strings must preserve the placeholder names verbatim (e.g. `{pkgs}`, `{n}`, `{elapsed:.1f}s`).
- Set `meta.lang_name` in the language's own script (e.g. `"meta.lang_name": "Deutsch"`).
- You can put your name in `meta.translator_credit` — it lands in this README table.
- Very short words (table headers "TUN", "ACC") are size-sensitive — column widths auto-fit, but keep them sane.

After PR is merged it joins the language set.
